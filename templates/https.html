HTTPS en la red local

Sin HTTPS, la contraseña y la sesión viajan en claro por la red: cualquiera conectado al mismo wifi puede leerlas. Como Let's Encrypt no emite certificados para direcciones como 192.168.1.50, aquí se crea una autoridad propia que se instala una vez en cada dispositivo.

1. Descarga el certificado

Es el certificado público de la autoridad. Instálalo en cada dispositivo desde el que entres al servidor.

Descargar el certificado (ca.crt)

Desde el móvil, abre esta dirección directamente en el navegador:
{{ request.scheme }}://{{ host_actual }}{{ url_for('descargar_ca') }}
No hace falta iniciar sesión, así que un dispositivo nuevo puede descargarlo sin más.

2. Instálalo

Windows

  1. Doble clic en servidor-archivos-ca.crt → Instalar certificado.
  2. Elige Equipo local (pedirá permiso de administrador).
  3. Marca Colocar todos los certificados en el siguiente almacén y elige Entidades de certificación raíz de confianza.
  4. Firefox usa su propio almacén: Ajustes → Privacidad y seguridad → Certificados → Ver certificados → Autoridades → Importar.

Android

  1. Ajustes → Seguridad → Cifrado y credenciales → Instalar un certificado → Certificado de CA, y elige el archivo descargado.
  2. Android avisará de que «la red podría estar supervisada». Es el aviso normal al instalar una CA propia.
  3. Chrome funcionará. Firefox en Android no usa el almacén del sistema y seguirá avisando.

iPhone y iPad

  1. Abre el enlace en Safari (Chrome en iOS no ofrece instalar perfiles) y acepta la descarga del perfil.
  2. Ajustes → Perfil descargado → Instalar.
  3. Este paso hace falta y es el que casi todo el mundo se salta: Ajustes → General → Información → Ajustes de confianza de certificados, y activa el interruptor de «{{ estado.huella_ca and 'Servidor de Archivos - CA local' }}». Sin esto el certificado está instalado pero iOS no confía en él, y el aviso sigue saliendo igual.

macOS y Linux

  1. macOS: doble clic → Acceso a Llaveros → busca el certificado → Obtener información → Confianza → Confiar siempre.
  2. Linux (Debian/Ubuntu): sudo cp ca.crt /usr/local/share/ca-certificates/servidor-archivos.crt && sudo update-ca-certificates

Para comprobar que has instalado el certificado correcto, su huella SHA-256 debe coincidir con la de arriba.

3. Reinicia el servidor

El HTTPS se activa al arrancar, así que hace falta reiniciar. En el servidor: docker compose restart. Después entra por https://{{ host_actual }}.

Mantenimiento

Úsalo si cambia la IP del servidor o si añades una dirección nueva. Se firma con la misma autoridad, así que los dispositivos que ya la tienen instalada no hay que tocarlos.
